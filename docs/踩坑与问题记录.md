## 1. 对账 FAILED 未回补库存，破坏库存守恒不变量

- **现象**：e2e 一致性不变量 G1 中 `2_stock_conservation` 违反 1 项。P1001 `available=95`，而按校验口径 `total(100) - sold(status∈{2,3,4}=3) = 97`，两者对不上。
- **根因**：库存回补行为在两条失败路径上不一致。
  - `ReceiptTimeoutTask`（超时无回执 → FAILED）会回补 DB + Redis 库存；
  - `ReceiptReconcileService`（金额不一致 `AMOUNT_MISMATCH` / 上游失败 `UPSTREAM_FAILED` → FAILED）**不回补**。
  - 终态 FAILED 订单仍占用预扣库存，而校验只把 `status∈{2,3,4}`（CREATED/REPORTED/CONFIRMED）计入已售，于是不变量被破坏。
- **解决**：`ReceiptReconcileService` 的两条 FAILED 分支调用新增的 `restoreStock(order)`（`stockMapper.restore` + `stockService.release`），与超时路径行为对齐；单测补充「失败回补、确认不回补」断言。
- **涉及文件**：
  - `src/main/java/com/fuzuyang/trading/application/service/ReceiptReconcileService.java`
  - `src/test/java/com/fuzuyang/trading/application/service/ReceiptReconcileServiceTest.java`
- **面试口径**：终态订单必须释放预留库存；本地 DB 为唯一事实来源，超时与对账两条失败路径需行为一致；一致性不变量校验的价值在于暴露路径间不一致。

## 2. 200 并发首连偶发 ClosedChannelException

- **现象**：`OrderConcurrencyLocalIT.shouldCreateOnlyOneOrderForSameKey` 报 `ExecutionException: java.net.ConnectException`（根因 `java.nio.channels.ClosedChannelException`）。但同批请求已触发 `DispatcherServlet` 初始化，说明服务本身可连，并非服务未就绪。
- **根因**：200 线程同时发起首连时，JDK `HttpClient` 连接池 + `localhost` 双栈（本机 `localhost` 先解析为 `::1`）回退存在竞态，个别连接在 `beginConnect` 阶段被关闭；而 `fire()` 对任意一个 `future.get` 异常即整体失败，导致用例偶发报错。
- **解决**：请求地址由 `localhost` 改为 `127.0.0.1` 规避双栈回退；`call()` 对传输层 `IOException` 做 3 次退避重试（下单接口幂等，重试安全）。
- **涉及文件**：`src/test/java/com/fuzuyang/trading/perf/OrderConcurrencyLocalIT.java`
- **面试口径**：区分「服务不可用」与「客户端连接池竞态」；幂等接口可安全重试；压测客户端需容忍瞬时网络抖动，否则会误报正确性问题。
